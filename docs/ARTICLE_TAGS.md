# 文章 Tags 交接说明（写稿 Agent 必读）

本文规定《超智全球视野》文章 frontmatter 中 `tags` 的**唯一合法结构**与**打标方法**。写稿 Agent 生成或修改文章时，必须按本文输出；禁止平面 `string[]`，禁止自造一级/二级键名。

权威 Schema：[`src/content.config.ts`](../src/content.config.ts) 中 `articleSchema.tags`。  
全文 frontmatter 规范见 [`ARTICLE_FORMAT.md`](./ARTICLE_FORMAT.md)。

---

## 1. 必填 YAML 骨架（四键 + 主体六子键，空也要写）

**每次写文章都必须输出完整结构。** 没有内容的类别写 `[]`，不要省略键。

```yaml
tags:
  科学智能体: []
  项目跟踪: []
  实施主体:
    企业: []
    超级计算机: []
    研究机构: []
    高校: []
    政府机构: []
    学会: []
  科学领域: []
```

硬性规则：

1. 一级四键固定且建议按此顺序书写：`科学智能体` → `项目跟踪` → `实施主体` → `科学领域`。
2. `实施主体` 下六子键固定：`企业` / `超级计算机` / `研究机构` / `高校` / `政府机构` / `学会`。
3. 四类合计（含主体任一子类）**至少 1 个**非空标签，否则 Zod 校验失败。
4. 标签值为非空字符串；同一数组内不要重复。

---

## 2. 四个一级类别分别装什么

| 一级类别 | 含义 | 该打 | 不该打 |
| --- | --- | --- | --- |
| **科学智能体** | 为科研提供便利的**平台、工具、助手、模型产品线** | `AMD HPC Assistant`、`Nemotron for Science`、`Sagebrush`、`Gemini` | 泛化词「科学智能体」「AI」「HPC」；单纯论文方法名（除非已产品化） |
| **项目跟踪** | 某主体开展的、可**长期跟踪进展**的项目/奖项/计划；期间可能多篇报道 | `创世纪计划`、`戈登贝尔奖`、`前沿观察计划`、`银河逐星模拟 PHEASANT`、`国家人工智能研究资源 NAIRR` | 一次性新闻事件名；机器型号本身（应归超级计算机） |
| **科学领域** | 进展所属的**科研领域** | `生物医药`、`量子算法`、`天文模拟`、`气候预测`、`聚变`、`药物设计` | `AI for Science`、`HPC`、`超智融合` 等过宽口号 |
| **实施主体** | 推进项目、贡献进展的**机构/系统**（再分六类，见下） | 公司、超算、实验室、高校、资助机构、学会 | 个人作者姓名（一般不打） |

### 2.1 实施主体六子类

| 子类 | 含义 | 示例 |
| --- | --- | --- |
| **企业** | 公司、商业实验室品牌 | `超威半导体 AMD`、`英伟达 NVIDIA`、`Google DeepMind` |
| **超级计算机** | 具体超算系统（含分区/加速段全称） | `Frontier（美国）`、`JUPITER Booster（德国）`、`Lux（美国）` |
| **研究机构** | 国家实验室、超算中心、国立研究所等 | `橡树岭国家实验室 ORNL`、`得克萨斯高级计算中心 TACC`、`理化学研究所 RIKEN` |
| **高校** | 大学 | `东京大学` |
| **政府机构** | 部委、基金会、部级计划主管部门 | `美国能源部 DOE`、`美国国家科学基金会 NSF` |
| **学会** | 学会/协会 | `中国计算机学会 CCF` |

归属拿不准时：

- 超算中心（TACC、CSC）→ **研究机构**，不要放进「超级计算机」。
- 超算整机/分区（Frontier、LUMI、JUPITER Booster）→ **超级计算机**。
- DOE / NSF → **政府机构**；ORNL / LLNL → **研究机构**。
- DeepMind、NVIDIA → **企业**。

## 3. 命名规范（必须遵守）

### 3.1 机构：中文名 + 英文缩写/专名

缩写单独出现可读性差时，写成「中文全称 + 空格 + 英文缩写/专名」：

- 正确：`得克萨斯高级计算中心 TACC`、`美国国家科学基金会 NSF`、`橡树岭国家实验室 ORNL`、`理化学研究所 RIKEN`
- 错误：只写 `TACC`、`NSF`、`ORNL`

品牌在中文语境已极常用、且文中一贯用英文品牌时，可用「中文通称 + 英文」：

- `超威半导体 AMD`、`英伟达 NVIDIA`
- `Google DeepMind`（无更稳妥中文专名时可保留英文专名）

### 3.2 超级计算机：系统全称 + （国家/地区）

- 正确：`Frontier（美国）`、`Aurora（美国）`、`El Capitan（美国）`、`LUMI（芬兰）`、`JUPITER Booster（德国）`、`灵晟 LineShine（中国）`
- 错误：只写 `JUPITER`（漏掉 Booster 等正式分区名）、漏国家、写错国家

国家按机房/运营主体所在地，不按厂商总部。拿不准时回原文或官方命名，不要猜。

### 3.3 项目跟踪：可读中文 + 必要英文专名

优先「中文说明 + 英文项目名」，便于主题页检索与聚合：

- `银河逐星模拟 PHEASANT`
- `蛋白质结构蒸馏工作流 ElMerFold`
- `时空Transformer观测重建建模 STORM`
- `国家人工智能研究资源 NAIRR`
- 已通行中文名可单独：`创世纪计划`、`戈登贝尔奖`、`前沿观察计划`

### 3.4 科学智能体 / 科学领域

- 科学智能体：用**产品或平台对外名称**，与正文一致（如 `Nemotron for Science`、`Sagebrush`）。
- 科学领域：用短领域词，宜具体（`气候预测` 优于 `地球科学`；`量子算法` 优于 `量子`）。一篇可有多个领域，但不要堆砌。

### 3.5 禁止的泛化标签

不要再打下列无效或过宽标签（历史遗留，已废弃）：

- `HPC`、`AI for Science`、`超智融合`
- 把类别名本身当标签：`科学智能体`（作为字符串标签）
- 无信息测试词（正式稿）；草稿测试除外

## 4. 从正文到 tags 的操作步骤

写完或改完正文后，按下列顺序填 tags（只依据**本文已写明且可靠**的信息，禁止臆造未出现的主体）：

1. **科学智能体**：文中是否发布/上线了可复用的科研工具、助手、推理服务、模型产品线？有则写入对外名称。
2. **项目跟踪**：是否属于可连续报道的计划、奖项、命名工程项目？有则写入规范化项目名；同一奖项/计划跨文保持字符串一致。
3. **科学领域**：这篇进展主要落在哪些科研领域？选 1–3 个最贴切的。
4. **实施主体**：拆出企业、超算、研究机构、高校、政府机构、学会；按 §3 命名；只收录对进展有实质贡献或运营关系的主体。
5. **自检**：
   - 四键 + 六子键是否齐全？
   - 空类是否为 `[]`？
   - 合计是否 ≥ 1？
   - 有无泛化禁词？
   - 超算是否带（国家）且名称完整？
   - 机构是否「中文 + 英文」？

## 6. 常见错误清单

| 错误 | 后果 / 改正 |
| --- | --- |
| `tags: [A, B]` 平面数组 | Schema 失败；必须用四键对象 |
| 省略空键 | 与仓库约定不一致；空类写 `[]` |
| `JUPITER` 代替 `JUPITER Booster（德国）` | 名称不准确；写正式系统名 + 国家 |
| 只写 `TACC` | 改为 `得克萨斯高级计算中心 TACC` |
| 打上 `HPC` / `AI for Science` | 禁止；改打具体领域或主体 |
| 把超算中心放进「超级计算机」 | 改放到「研究机构」 |
| 杜撰文中未出现的机构/超算 | 禁止；只标正文有据者 |
| 同一项目在不同文章用不同字符串 | 破坏主题聚合；沿用已有规范名 |

## 7. 与主题页的关系（Agent 需知）

- 主题页按一级类别展示；`实施主体` 下再按六子类分区。
- 标签字符串即主题 URL 键：拼写不一致会变成两个主题。
- 详情页/卡片上的 pill 是按类别顺序**展平**后的标签列表。

写稿 Agent **不必**改前端渲染代码；只需输出合法 `tags`。

- [ ] 项目名可跟踪且跨文一致  
- [ ] 每个标签都能在正文中找到依据
